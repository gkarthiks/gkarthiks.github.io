01 / ORACLE

Changing the network.
Keeping the confidence.

A live Kubernetes fleet needs a migration strategy as carefully engineered as its destination. I built Go automation for the transition from Flannel to Cilium, with phased rollout, validation, and recovery built into the process.

  • Go
  • Cilium / eBPF
  • Kubernetes
The engineering decisions +

Separate CNI replacement from kube-proxy replacement to reduce the scope of each change. Validate networking at each stage, make retries deliberate, and document how operators diagnose and recover a migration.

The work extended into policy enforcement, network observability, and service-mesh migration planning.

02 / BLACKROCK

A shorter path
from idea to infrastructure.

I architected a self-service Kubernetes platform that brought provisioning from days to minutes. Cluster API and ArgoCD turned infrastructure setup into a repeatable path, with delivery pipelines and observability available from the start.

  • Cluster API
  • ArgoCD
  • Multi-tenancy
The engineering decisions +

Make the supported path easy to adopt. Combine declarative provisioning with sensible defaults and opt-in capabilities, so teams can get started without becoming infrastructure specialists.

Evaluate virtual clusters and hierarchical namespaces to provide isolation while limiting physical cluster sprawl.

I own and evolve Temporal operations across upgrades, namespace authorization, capacity, history cleanup, and incident response. The goal is durable execution supported by equally durable operational practices.

The engineering decisions +
